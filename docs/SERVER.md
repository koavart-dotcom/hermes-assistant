# Серверный режим (hermesd) — Windows Server 2022 (и Mac для тестов)

Тот же установщик `Hermes Assistant_x.y_x64-setup.exe`, что и для ПК. Внутри него есть
`hermesd.exe`: ядро приложения (`crates/hermes-core`) без окна, в виде службы Windows
«Hermes Assistant Server». Решение — ADR 18.10.2026 в `docs/decisions.md`, этап 9 в `docs/ROADMAP.md`.

## Что делает служба

- При первом запуске ставит Hermes Agent: стадии `install.ps1`, та же закреплённая версия, что на ПК.
  Ollama, локальные модели, голос и быстрые команды ПК на сервер не ставятся. Если установка
  упала (например, нет сети), служба повторяет её с паузой 4, 8, 16, 30 мин.
- Настраивает Hermes: `approvals.mode: manual`, api_server с ключом, наши плагины
  (`hermes_permissions`) и skills.
- Раз в минуту проверяет gateway Hermes (`/health` на 8642) и поднимает его, если он упал.
  Если запуск не удался, пробует снова через 1, 2, 4 … 30 мин.
- Держит Control API на `127.0.0.1:8645` с теми же маршрутами, что у приложения
  (`docs/CONTROL_API.md`): статус, установка, `config.yaml`, ключи `.env`, перезапуск gateway,
  команды `hermes`, журналы, политика разрешений, чат с подтверждениями. Порт 8643 остаётся
  за приложением, поэтому оба могут работать на одной машине.
- Когда служба останавливается, она останавливает и gateway.

## Где что лежит

| Что | Путь |
|---|---|
| Программа | `C:\Program Files\Hermes Assistant Server\hermesd.exe` + `resources\` |
| Данные (корень) | `C:\ProgramData\Hermes Assistant Server\`: права только у SYSTEM, Administrators и учётной записи службы |
| Hermes Agent | `…\Hermes Assistant Server\hermes\` (`HERMES_HOME`) |
| Ключ Control API | `…\Hermes Assistant Server\ua.koavart.hermes\control.token` |
| Журнал службы | `…\Hermes Assistant Server\ua.koavart.hermes\logs\hermesd.log` (UTC) |

Корень можно переопределить переменной `HERMES_SERVER_ROOT`, порт Control API — переменной
`HERMES_CONTROL_PORT` (в окружении службы).

## Установка

1. На сервере запустить установщик под администратором.
2. На вопрос «Установить Hermes как серверную службу Windows?» ответить «Да». Вопрос задаётся
   один раз на пользователя и не появляется при автообновлении.
3. В открывшейся консоли (с запросом UAC) выбрать учётную запись службы:
   - **Enter** — виртуальная учётка `NT SERVICE\HermesAssistant`: без пароля, право «Вход в
     качестве службы» получает сама. В сети она выступает как учётка компьютера
     (`DEKA\SERVER$`), значит доступ по WinRM выдаётся именно ей.
   - **`DOMAIN\svc-hermes`** — доменная служебная учётка. Консоль спросит пароль. Право «Вход
     в качестве службы» выдаётся через GPO или `secpol.msc`, иначе служба не стартует
     (ошибка 1069).
4. Консоль копирует файлы в Program Files, создаёт службу (автозапуск с задержкой,
   перезапуск при сбое через 30 с), выставляет права на папку данных и запускает службу.

Вручную, из PowerShell под администратором:

```powershell
& "$env:LOCALAPPDATA\Hermes Assistant\resources\server\hermesd.exe" install                       # виртуальная учётка
& "$env:LOCALAPPDATA\Hermes Assistant\resources\server\hermesd.exe" install --account DEKA\svc-hermes
& "C:\Program Files\Hermes Assistant Server\hermesd.exe" status
& "C:\Program Files\Hermes Assistant Server\hermesd.exe" uninstall                                 # данные остаются
& "C:\Program Files\Hermes Assistant Server\hermesd.exe" run                                       # в консоли, для отладки (службу сначала остановить)
```

**Обновление службы — само** (с v0.33.0):
- Каждый релиз публикует `hermesd-windows-x64.zip` (hermesd + resources) и манифест `hermesd.json`.
  Пакет подписан тем же ключом, что и обновления приложения.
- Служба проверяет `releases/latest/download/hermesd.json` через 2 минуты после старта, а дальше
  раз в 6 часов. Есть новая версия и включено автообновление — служба скачивает пакет, проверяет
  подпись (если она не совпала, ничего не меняется) и подменяет файлы в Program Files:
  `hermesd.exe` переименовывается в `hermesd.old.exe`, на его место встаёт новый, папки resources
  заменяются. Затем служба завершается с кодом 1, и SCM по правилу «перезапуск при сбое»
  поднимает новую версию примерно через 30 секунд. Hermes Agent (gateway) при этом не
  останавливается.
- После старта новая версия удаляет `hermesd.old.exe` и пишет в Telegram
  «Hermes Server обновлён: X → Y».
- Во время установки Hermes Agent или починки обновление не начинается.
- В панели («Обзор → Обновление службы») видно версию и последнюю проверку. Там же кнопки
  «Проверить» и «Обновить до …» и переключатель автообновления. Через API:
  `GET/PUT /server/update`, `POST /server/update/check`, `POST /server/update/apply`.
- Чтобы служба могла заменить свои файлы, `hermesd install` даёт её учётке право Modify на
  `C:\Program Files\Hermes Assistant Server`.
- Службы, поставленные до v0.33.0, один раз обновляются вручную: `hermesd install` из нового
  приложения.

## Веб-панель

Служба раздаёт веб-панель на том же адресе, что и Control API: **http://127.0.0.1:8645/ui/**.
Вход — по ключу Control API (`control.token`, см. таблицу выше). Ключ остаётся во вкладке браузера,
галочка «Запомнить» сохраняет его в браузере. Разделы:

| Раздел | Что там |
|---|---|
| Обзор | состояние Hermes Agent (установить / перезапустить), ход установки, сводка по алертам и инвентарю |
| Инциденты | последние 200 инцидентов Wazuh с разбором и итогом проверок, кнопка «Тестовый алерт» |
| Инвентарь | таблица хостов: добавить, изменить, удалить, «Проверить» (проверки только на чтение с выводом), ключ SSH службы и подсказки по подготовке машин |
| Wazuh | приём алертов, фильтры, разбор и проверки, Telegram; сохранение применяется сразу; готовый блок для `ossec.conf` |
| Модель и ключи | модель разбора (облако или Jarvis Deka), ключи `.env` Hermes (видны только 4 последних символа), перезапуск Hermes |
| Журнал | `hermesd.log`, обновляется раз в 10 секунд |

Как открыть:
- **На самом сервере** (RDP): браузер → `http://127.0.0.1:8645/ui/`, мастер-ключ или ключ доступа.
- **По сети по HTTPS** (раздел «Доступ», ниже): `https://<сервер>:8443/ui/`, только ключ доступа.
- Через SSH-туннель: `ssh -L 8645:127.0.0.1:8645 <сервер>` → `http://127.0.0.1:8645/ui/`.

## Доступ по сети (HTTPS) и ключи

Раздел панели **«Доступ»** (виден только администратору). По умолчанию выключен.

**Ключи доступа.** Каждому человеку выдаётся свой ключ с ролью:
- **чтение** — смотреть всё, кроме секретов (блок для `ossec.conf`, `.env`, `config.yaml`, список
  ключей). Менять ничего нельзя: любой запрос, кроме GET, сервер отклоняет (403). Проверки и починка
  тоже недоступны.
- **администратор** — всё, включая починку и выдачу ключей.

Ключ (`hk_…`) показывается один раз при создании, служба хранит только его SHA-256
(`access.json`). Отозвать ключ — кнопка с корзиной. Имя владельца ключа попадает в журнал починок и
в Telegram. Мастер-ключ `control.token` работает только на самом сервере (127.0.0.1).

**HTTPS.**

| Настройка | Что значит |
|---|---|
| Включить | запускает приёмник; применяется сразу, без перезапуска службы |
| Адрес | `0.0.0.0:8443` по умолчанию |
| Разрешённые сети | `10.10.0.0/24, 192.168.229.15`; без этого списка включить нельзя; подключения из других сетей сбрасываются до TLS |
| Сертификат и ключ (PEM) | пути на сервере, например сертификат от доменного ЦС; пусто — самоподписанный |
| Доп. имена | DNS-имена для самоподписанного; имя компьютера и FQDN добавляются сами |

Для самоподписанного сертификата панель показывает **отпечаток SHA-256**. При первом входе браузер
предупредит о недоверенном сертификате — сверьте отпечаток с панелью на сервере и только потом
продолжайте. Лучше выпустить сертификат в доменном ЦС, тогда предупреждения не будет.

Также по сети:
- каждый ответ несёт HSTS;
- после 10 неверных ключей за 10 минут адрес получает 429 на 10 минут (счётчик живёт до перезапуска службы);
- приёмник отвечает только по TLS 1.2/1.3 (rustls).

Брандмауэр Windows, под администратором:

```powershell
New-NetFirewallRule -DisplayName "Hermes panel HTTPS" -Direction Inbound -Protocol TCP -LocalPort 8443 -RemoteAddress 10.10.0.0/24 -Action Allow
```

Разработка: `pnpm dev:server` поднимает панель на http://127.0.0.1:1430/ui/ с прокси на hermesd,
запущенный на этой же машине (`hermesd run`). Сборка: `pnpm build` собирает и окно приложения,
и `dist-server/`. Установщик кладёт `dist-server/` в `resources/server-ui/`, а `hermesd install`
копирует её в Program Files.

## macOS (Mac mini) — тестовый стенд

С v0.34.0 та же служба собирается для Mac на Apple Silicon. Это launchd-демон
`ua.koavart.hermesd`. Решение — ADR 19.10.2026 в `docs/decisions.md`. Подходит для проверки
Linux-части: приём алертов, разбор, панель, диагностика и починка Linux-машин по SSH.
**Windows-машины с Мака не диагностируются**: нет WinRM/JEA и доменной учётки, и служба
отвечает «WinRM runs only from the Windows server». Для этого остаётся Windows Server.

| Что | Путь |
|---|---|
| Программа | `/usr/local/hermes-server/hermesd` + `resources/` (владелец — учётка службы, для самообновления) |
| Данные (корень) | `/usr/local/var/hermes-server/` (права 700, владелец — учётка службы) |
| HOME службы | `/usr/local/var/hermes-server/home`. Свой HOME, поэтому `~/.hermes` и `~/.local/bin` пользователя не трогаются |
| Ключ Control API | `/usr/local/var/hermes-server/ua.koavart.hermes/control.token` |
| Журнал | `…/ua.koavart.hermes/logs/hermesd.log`, вывод процесса — `hermesd.stdout.log` |
| Описание демона | `/Library/LaunchDaemons/ua.koavart.hermesd.plist` |

**Установка:** одна команда в терминале на Маке, sudo спросит пароль:

```bash
curl -fsSL https://raw.githubusercontent.com/koavart-dotcom/hermes-assistant/main/tools/server/install-macos.sh | bash
```

Скрипт берёт `hermesd-macos-arm64.zip` из последнего релиза и запускает
`sudo hermesd install --user <текущий пользователь>`. Демон работает от этого пользователя,
не от root. Запуск при загрузке; при сбое перезапуск через 30 с
(`KeepAlive.SuccessfulExit=false`).

- Hermes Agent ставится его собственным `install.sh` с той же закреплённой версией и теми
  же стадиями, что `install.ps1`. Нужны git и curl: на Маке это Command Line Tools
  (`xcode-select --install`).
- Gateway на Маке запускает сама служба: `hermes gateway run --replace --external-supervisor`
  в отдельной группе процессов, pid лежит в `gateway.pid`. Сторож поднимает его, если он упал.
  При остановке службы gateway получает SIGTERM. При перезапуске ради обновления gateway
  продолжает работать (`AbandonProcessGroup`).
- Ключ api_server хранится файлом в папке данных (`HERMES_SECRETS_FILE_ONLY=1`). У демона
  нет связки ключей пользователя.
- Самообновление работает так же, как на Windows: манифест `hermesd-macos-arm64.json`, файлы
  `hermesd` → `hermesd.old`, после замены выход с кодом 1, и launchd поднимает новую версию.
- Управление: `HERMES_TARGET=mac tools/hermesctl.sh status`. Это SSH-туннель на 8645, ключ
  читается по SSH. Панель: `http://127.0.0.1:8645/ui/` на самом Маке или по сети через
  HTTPS (раздел «Доступ»).
- Чтобы стенд не засыпал: «Системные настройки → Энергосбережение → не переходить в режим
  сна», или `sudo pmset -a sleep 0 disksleep 0`.

```bash
sudo /usr/local/hermes-server/hermesd status
sudo /usr/local/hermes-server/hermesd uninstall      # данные и программа остаются
sudo launchctl kickstart -k system/ua.koavart.hermesd  # перезапуск
```

Тот же код работает и на Linux как systemd-юнит (`/opt/hermes-server`,
`/var/lib/hermes-server`, `sudo hermesd install --user NAME`). Готовый пакет для Linux пока
не публикуется.

## Управление без окна

- **С сервера разработки:** `HERMES_TARGET=server HERMES_PC=<сервер> tools/hermesctl.sh status`.
  Скрипт поднимает SSH-туннель на 8645, а ключ берёт из ProgramData (кэш —
  `private/control-<сервер>.token`).
- **Модель:** `tools/hermesctl.sh model-set …` и `key-set ANTHROPIC_API_KEY …`, затем
  `gateway-restart`. Модель на сервере не выбирается при установке, её задают отдельно.
- **Веб-панель** (выше) — то же самое кнопками.
- **Из приложения на ПК:** раздел «Серверы» (планируется).

## Ограничения (на 18.10.2026)

- Не проверено на реальном Windows Server: запуск под виртуальной учёткой, `install.ps1` в
  профиле службы, `hermes gateway start` без интерактивного сеанса.
- Если на той же машине через окно настроить ещё и «настольный» Hermes, они будут спорить
  за порт api_server 8642. На сервере окно приложения не настраивать, пока нет раздела «Серверы».
- HTTPS по сети проверен локально (self-signed, роли, блокировка, белый список, HSTS); на Windows
  Server и с сертификатом доменного ЦС — не проверен.
