# Фоновые сценарии агента для Deka (черновик 11.10.2026)

Агент живёт на Mac mini M4 дома, задачи запускает планировщик Hermes (cron), отчёты и подтверждения —
в Telegram. Рабочие данные (тексты заявок, логи) обрабатывает локальная модель; в облако уходят
только обезличенные задачи или то, что Артем явно разрешил.

## Общие предпосылки (нужны для всего)
| Что | Зачем |
|---|---|
| Сетевой доступ Mac → сеть Deka (VPN или Tailscale) | без него агент видит только публичные API |
| Отдельная сервисная учётка агента в каждой системе, минимальные права, отзываемая | аудит и быстрый откат при ошибке |
| Токены: FreeScout, Jira, GitLab, Sentry, kubeconfig (read-only), SSH-ключ агента | хранить в Keychain Mac / `private/` |
| Журнал действий агента (что сделал, по чьему разрешению) | обязателен до любой автопочинки |
| Allowlist «что можно без спроса» + Telegram-подтверждение на всё остальное | уровни L0 / L1 / L2 из CLAUDE.md |

## Сценарии
| # | Сценарий | Что делает в фоне | Что нужно | Уровень |
|---|---|---|---|---|
| 1 | Триаж хелпдеска | Каждые 5–10 мин читает новые заявки FreeScout, классифицирует (сеть / ПК / 1С / доступы / принтеры), ищет дубли и похожие закрытые, назначает очередь, пишет черновик ответа и внутреннюю заметку, следит за SLA | API FreeScout (уже есть в `/helpdesk`), справочник категорий, локальная модель | L0 |
| 2 | Автопочинка типовых заявок | По рецептам из allowlist: перезапуск службы, очистка диска, переустановка принтера, сброс сессии, разблокировка учётки; результат — в заявку и в Telegram | WinRM/SSH к рабочим станциям и серверам, сервисная учётка, 5–10 написанных runbook'ов | L1 |
| 3 | Сторож инфраструктуры | k8s: CrashLoop, OOM, Pending, место на PVC; сертификаты ≤ 14 дней; диски серверов; очередь почтового сервера; DNS; успешность ночных бэкапов. Известное — чинит (перезапуск deployment из allowlist), остальное — алерт | kubeconfig read-only (+ отдельный RBAC на restart выбранных deployment), SSH «monitoring», доступ к почтовику | L1 |
| 4 | Дежурный по Sentry | Новые issue и всплески ошибок на проде → находит коммит/MR-виновник, пишет разбор в Jira или комментарий к MR | Sentry token, GitLab token (read + comment) | L0 |
| 5 | Смотритель CI/CD | Упавший пайплайн GitLab → читает лог, объясняет причину, предлагает патч комментарием к MR; напоминает об MR без ревью > 2 дней; проверяет, что `openapi.json` собрался на теге | GitLab token, доступ к `registry.dekastore.eu` (read) | L0 |
| 6 | Утренняя сводка | 08:30 в Telegram: Jira ADM/DEKA/FE (мои, просроченные, новые), заявки за ночь, инциденты, упавшие пайплайны, состояние кластера, что сделал сам | токены Jira / FreeScout / GitLab, cron | L0 |
| 7 | Гигиена Jira | Задачи без исполнителя/оценки, «In Progress» > N дней, заявки хелпдеска без связанной задачи; повторяющиеся заявки → предложение завести задачу | Jira token (write — только после подтверждения) | L0/L2 |
| 8 | Пополнение wiki | Раз в неделю: закрытые заявки → черновики статей-инструкций по стандарту (функциональная схема первой, Mermaid); проверка битых ссылок и устаревших версий в статьях | API wiki Deka, FreeScout read, скил `/design-doc-mermaid` | L0 |
| 9 | Экраны в 16 магазинах | Проверка, что панели MagicInfo онлайн и крутят актуальный контент; скриншот/статус → алерт при простое > 30 мин | доступ к серверу MagicInfo (API или веб), список панелей | L0 |
| 10 | Филиалы и объекты | VPN-туннели до магазинов и электростанции (ADM-108), камеры, UPS; при падении — попытка поднять туннель, иначе алерт | SNMP/API маршрутизаторов, список объектов с ожидаемым состоянием | L1 |
| 11 | 1С / Хронос / МЕ.ДОК | Логи ночных обменов и регламентных заданий, обновления МЕ.ДОК, место на дисках серверов 1С; сводка бухгалтерии при сбое | доступ к логам по SSH/SMB, список заданий | L0 |
| 12 | Почта и домен | Очередь, RBL-листы, срок сертификатов, разбор DMARC-отчётов в читаемую сводку | SSH к почтовику, доступ к ящику DMARC | L0 |

| 14 | Безопасность | Новые учётки в AD, всплеск неудачных входов, админские права вне списка, истекающие пароли и сертификаты | AD read, логи DC / SIEM | L0 |

| 16 | Инвентаризация | Раз в неделю собирает с ПК железо, ПО, лицензии, свободное место → таблица, diff с прошлой неделей | WinRM, сервисная учётка | L0 |
| 17 | Расшифровка совещаний | Запись → текст (Whisper локально) → протокол с задачами → черновики в Jira | микрофон/записи, локальная модель; ничего не уходит в облако | L0/L2 |
| 18 | Поддержка RAG-бота | Ночная переиндексация wiki, A/B-сверка ответов Qdrant vs wiki (фаза 3 из Kanban) | доступ к Qdrant и wiki API | L0 |

## С чего начать (минимум подключений, быстрый эффект)
1. Утренняя сводка (6) — три токена и cron, ничего не меняет.
2. Триаж хелпдеска (1) — API уже обёрнут, даёт данные для allowlist автопочинки.
3. Сторож инфраструктуры в режиме «только алерты» (3) — read-only доступы.
4. Смотритель CI/CD и Sentry (4, 5) — read + комментарии.
Через месяц журнала — переводить самые частые повторы в L1-рецепты (2).
