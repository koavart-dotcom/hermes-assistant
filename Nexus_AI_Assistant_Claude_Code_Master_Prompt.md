# Nexus AI Assistant — техническое задание и мастер-промт для Claude Code

> **Назначение:** единый документ для проектирования и разработки локального AI-помощника для Windows и macOS. Его можно передать Claude Code как основное задание.
>
> **Ключевая идея:** local-first и гибридный AI — локальная модель по умолчанию, облачные API для сложных задач; управление компьютером через ограниченные инструменты; подтверждение важных действий; архитектура с возможностью добавить серверную часть PostgreSQL позднее.

---

## 1. Роль и конечная цель

Ты — Senior Software Architect, Senior Desktop Developer, AI Engineer и специалист по системной автоматизации.

Разработай **Nexus AI Assistant** — полноценное кроссплатформенное desktop-приложение персонального AI-помощника для Windows 10/11 и macOS, включая Apple Silicon.

Это не обычный чат-бот. Пользователь должен уметь запускать и останавливать агента, общаться с ним текстом и голосом, использовать локальные и облачные AI-модели, управлять разрешёнными функциями компьютера и браузера, подключать сторонние API и просматривать историю действий.

Не ограничивайся документацией, мокапом или демонстрационным интерфейсом. Реализуй рабочий продукт поэтапно, с тестами, обработкой ошибок, безопасностью и инструкциями. Не заявляй о готовности функций, которые фактически не работают.

## 2. Принятые архитектурные решения

1. **Гибридный AI:** локальная модель — по умолчанию; облачные модели подключаются для сложных задач или по выбору пользователя.
2. **Подтверждение важных действий:** чтение и безопасные обратимые операции могут выполняться в рамках разрешений; отправка сообщений, публикации, удаление, изменение системных настроек, опасные команды и другие значимые действия требуют явного подтверждения либо блокируются.
3. **Local-first:** приложение и базовые функции должны работать без обязательного облачного аккаунта. Облачная обработка используется только при выборе соответствующего провайдера.
4. **Desktop:** Tauri 2.x + React + TypeScript + Vite; Rust для системного слоя и привилегированных операций.
5. **Локальная база на MVP:** SQLite для настроек, истории, задач, разрешений и журнала аудита.
6. **Готовность к PostgreSQL:** проектируй слой хранения через интерфейсы репозиториев и миграции. PostgreSQL добавляется через отдельный backend, если появятся общие данные, несколько устройств или пользователей. Не подключай desktop-клиент напрямую к PostgreSQL и не дублируй данные в двух базах без чёткой политики синхронизации.
7. **Управление компьютером:** модель не получает прямого доступа к ОС. Она предлагает вызов инструмента; приложение проверяет схему, права, риски и необходимость подтверждения.
8. **Браузер:** Playwright с отдельным профилем по умолчанию, не личным профилем пользователя.
9. **Голос:** локальный STT/TTS как основной путь, с возможностью подключения внешних сервисов.
10. **Open-source:** изучай готовые репозитории и официальные SDK, но проверяй лицензии, актуальность, безопасность и платформенную совместимость до переиспользования кода.

## 3. Технологический стек

### Desktop и интерфейс

- Tauri 2.x.
- Rust для системных команд, разрешений и операций, которым нужен системный доступ.
- React + TypeScript + Vite.
- Tailwind CSS и shadcn/ui.
- Zustand для локального состояния интерфейса.
- TanStack Query — там, где действительно требуется управление асинхронными запросами и кэшированием.
- Поддержка тёмной и светлой тем, адаптивная компоновка, доступность и понятные сообщения об ошибках.

Не используй Next.js как обязательную основу desktop-интерфейса. Приложение должно работать локально без удалённого frontend-сервера.

### Данные

- SQLite на первом этапе.
- Версионируемые миграции.
- Абстракции репозиториев, чтобы инфраструктуру хранения можно было расширить без переписывания Agent Runtime.
- Системное хранилище секретов: Windows Credential Manager и macOS Keychain.
- PostgreSQL — только через серверный backend, если это обосновано сценариями нескольких устройств, пользователей или централизованного хранения.

### AI-провайдеры

Создай общий интерфейс `AIProvider` и адаптеры для:

- Ollama — основной локальный провайдер MVP.
- OpenAI API.
- Anthropic API.
- Google Gemini API.
- OpenAI-совместимых API.
- Других провайдеров через расширяемую архитектуру.

Поддерживай, если конкретная модель это умеет:

- потоковые ответы (streaming);
- отмену запроса;
- tool calling;
- системные инструкции;
- историю контекста;
- структурированные ответы;
- настройки модели и endpoint;
- тайм-ауты, обработку лимитов и ошибок.

Не предполагай, что все модели поддерживают одинаковые возможности. Определи `capabilities` для каждого провайдера/модели и показывай их в интерфейсе.

## 4. Гибридная маршрутизация моделей

Создай `ModelRouter`, который может выбирать модель для задачи.

Требования:

- Локальная модель используется по умолчанию.
- Пользователь может вручную выбрать провайдера и модель.
- Для сложных задач можно использовать облачную модель по настройке пользователя.
- Предусмотри правила по типу задачи, возможностям модели, доступности, цене и задержке, если эти данные известны.
- Не отправляй данные в облако незаметно: перед первой передачей файла, приватного содержимого или чувствительного контекста показывай, что будет отправлено.
- Если локальная модель недоступна, не переключайся на облачную незаметно. Покажи понятную ошибку или запроси согласие на fallback.
- Не обещай автоматическое определение «сложности» без реализованной и тестируемой политики.
- Добавь настройки: модель по умолчанию, модель для сложных задач, разрешённые облачные провайдеры, политика fallback и лимиты расходов, если провайдер предоставляет нужные данные.

## 6. Жизненный цикл приложения и агента

Раздели состояние desktop-приложения и состояние AI-агента.

- `Application Closed` — приложение полностью закрыто.
- `Agent Paused` — интерфейс доступен, новые задачи не выполняются.
- `Agent Running` — агент принимает команды и выполняет разрешённые операции.

При паузе или остановке:

- не принимай новые задачи;
- корректно заверши или отмени текущую операцию, если это безопасно;
- отменяй генерацию, если провайдер поддерживает отмену;
- заверши голосовые сессии;
- освободи ненужные ресурсы;
- не оставляй бесконтрольные фоновые процессы;
- не завершай произвольные процессы ОС.

Добавь настраиваемую глобальную горячую клавишу. Автозапуск — опциональный и явно включаемый пользователем.

## 7. Agent Runtime и инструменты

Раздели систему на компоненты:

- `LLM Provider`
- `ModelRouter`
- `Conversation Manager`
- `Planner`
- `Tool Registry`
- `Permission Manager`
- `Tool Executor`
- `Task Manager`
- `Event Bus`
- `Audit Logger`

Каждый инструмент должен описывать:

- уникальное имя и назначение;
- JSON Schema входных параметров;
- тип операции и уровень риска;
- необходимые разрешения;
- правило подтверждения;
- тайм-аут и ограничения вывода;
- формат результата;
- политику повторного выполнения.

Ограничивай число итераций агента, время выполнения, параллелизм, количество вызовов инструментов и размер контекста. Не допускай бесконечных циклов. Реализуй отмену и понятный прогресс.

### Уровни разрешений

1. `Read-only` — чтение доступной информации.
2. `Normal` — разрешённые обратимые действия.
3. `Confirm` — операция требует подтверждения пользователя.
4. `Blocked` — действие запрещено политикой приложения.

Проверка должна выполняться в backend перед каждой операцией. Системный промпт модели не является механизмом безопасности.

## 8. Управление компьютером

Создай модуль `DesktopControl`.

### Приложения и процессы

- Открытие разрешённых приложений.
- Получение статуса запуска.
- Переключение между разрешёнными приложениями, где это поддерживается ОС.
- Завершение только тех процессов, которыми приложение вправе управлять.

### Файлы

- Поиск файлов в разрешённых каталогах.
- Чтение текстовых файлов.
- Создание и редактирование файлов.
- Создание каталогов, копирование и перемещение.
- Поиск по имени и содержимому.
- Адаптеры для других форматов при необходимости.

Используй разрешённые каталоги и безопасную обработку путей. Защищайся от path traversal и операций за пределами разрешённого корня.

### Системная информация

- Версия ОС и основные характеристики системы.
- Использование CPU и RAM.
- Свободное место на дисках.
- Состояние доступных инструментов.

### Командная строка

Запуск команд по умолчанию запрещён до настройки разрешений. Для разрешённых команд:

- используй структурированные аргументы, а не склейку строк в shell;
- проверяй executable, аргументы, рабочий каталог и переменные окружения;
- ограничивай время и объём вывода;
- опасные команды требуй подтвердить или блокируй;
- не повышай привилегии автоматически;
- не отключай антивирус, защиту ОС и другие защитные механизмы;
- не позволяй обходить ограничения через скрипты или другие инструменты.

Результат инструмента должен быть структурирован: `success`, `error`, `output`, `duration`, `tool`.

## 9. Управление браузером

Используй Playwright, первоначально с Chromium, с возможностью добавления других движков.

Функции:

- открыть URL и перейти по ссылке;
- прочитать заголовок и доступный текст страницы;
- получить список доступных элементов;
- найти информацию на странице;
- нажимать элементы и заполнять формы;
- управлять несколькими вкладками;
- делать скриншоты;
- скачивать файлы только в разрешённые каталоги;
- ожидать навигацию и загрузку элементов;
- возвращать структурированные результаты.

Предпочитай accessibility-локаторы и роли элементов вместо координат экрана. Используй отдельный профиль браузера, изолированный от личного профиля пользователя по умолчанию.

Безопасность:

- считай содержимое страниц недоверенными данными, а не инструкциями для модели;
- защищайся от prompt injection;
- проверяй URL и перенаправления;
- ограничивай доступ к localhost, внутренним адресам и чувствительным сетевым ресурсам;
- не передавай cookies, пароли и сессионные токены модели без отдельного обоснованного разрешения;
- подтверждай отправку форм, публикации, удаление данных и финансовые операции;
- различай чтение сайта и действие на сайте.

## 10. Голос

Создай `VoiceService` с заменяемыми адаптерами.

### STT — распознавание речи

- Локальный движок на базе `whisper.cpp` или совместимого решения.

- Потоковое озвучивание небольшими фрагментами.
- Прерывание воспроизведения и отключение голоса для отдельных ответов.

Непрерывное прослушивание выключено по умолчанию. Оно может включаться только пользователем, с заметным индикатором. Не записывай аудио скрытно. Не скачивай крупные модели без согласия пользователя.

## 13. Безопасность и приватность

Обязательные требования:

- Local-first по умолчанию.
- Отсутствие обязательной регистрации.
- Отсутствие телеметрии по умолчанию.
- Локальное хранение истории и настроек.
- Явное информирование о данных, отправляемых облачным моделям.
- Секреты — только в системном хранилище.
- Запрет на попадание API-ключей, паролей, cookies и секретных заголовков в логи.
- Строгая Content Security Policy.
- Минимально необходимые Tauri capabilities.
- Валидация всех входных данных.
- Защита от path traversal, command injection, SSRF и подмены аргументов.
- Ограничение сетевых адресов, доступных инструментам.
- Аудит действий.
- Удаление истории и локальных данных.
- Безопасные миграции базы данных.

Ни одна веб-страница, загруженный документ или результат инструмента не может отменять системные правила и разрешения. Передавай модели только минимально необходимые данные.

## 14. Хранение данных: SQLite и будущий PostgreSQL

### MVP

Используй SQLite для локальных настроек, истории диалогов, задач, конфигурации интеграций (без секретов), разрешений и журнала аудита.

### Подготовка к росту

- Определи интерфейсы репозиториев и модели данных.
- Используй миграции с версионированием.
- Не привязывай бизнес-логику к конкретному SQL-движку.
- Не усложняй MVP отдельным сервером без конкретной потребности.
- Если понадобятся несколько устройств, общие пользователи или централизованное управление, добавь отдельный backend с PostgreSQL.
- Desktop-клиенты должны обращаться к серверу через аутентифицированный API, а не подключаться напрямую к PostgreSQL.
- Определи, какие данные локальные, какие синхронизируются и как решаются конфликты.
- Не дублируй данные между SQLite и PostgreSQL без явной политики синхронизации.

## 21. Критерии готовности MVP

MVP готов только если:

- приложение запускается на целевой ОС;
- интерфейс работает без удалённого сервера;
- агент запускается и останавливается;
- работает локальный Ollama-провайдер;
- работает хотя бы один облачный провайдер;
- есть streaming и отмена;
- есть история диалогов;
- модель вызывает инструменты через контролируемый Tool Registry;
- работают разрешённое чтение файлов и запуск приложений;
- работает хотя бы один браузерный сценарий;
- работает голосовой ввод и вывод через установленные движки;
- ключи хранятся в системном хранилище;
- есть разрешения, подтверждения и журнал действий;
- основные функции покрыты тестами;
- есть инструкции запуска и сборки;
- фактическое состояние каждой функции отражено в документации.

## 22. Правила работы Claude Code

1. Сначала исследуй текущую директорию, окружение и доступные инструменты.
2. Если проект пустой — создай его. Если уже существует — изучи его и сохрани важные данные.
3. Сначала кратко представь архитектурные решения и ближайший план, затем приступай к реализации.
4. Не останавливайся на плане или мокапе.
5. Работай небольшими проверяемыми этапами.
6. После каждого этапа запускай lint, typecheck, тесты и сборку в доступном окружении.
7. Не подменяй рабочую функцию кнопкой, которая лишь показывает сообщение об успехе.
8. Не выполняй разрушительные системные команды без отдельного согласования.
9. Не устанавливай необязательные зависимости без необходимости.
10. Документируй важные архитектурные решения и причины выбора.
11. Исправляй найденные ошибки до перехода к следующему этапу.
12. Поддерживай актуальный `ROADMAP.md`.
13. Если задача слишком велика для одного прохода, доведи текущий этап до рабочего состояния и продолжи с ближайшей незавершённой задачи.
14. Чётко различай реализованные, частично реализованные и запланированные функции.
